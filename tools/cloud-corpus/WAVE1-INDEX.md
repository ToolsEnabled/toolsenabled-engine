# Wave one of the 1500-lane program — 6 swarms x 150, all report-only hunts

Generated by stamp-wave1.py; validated 900/900 by check-corpus.mjs (default
GUARDS.md); refutation-sampled 16 briefs via parallel adversarial agents: one
FATAL (a file newer than the website mirror — resolved by the mandatory
post-release mirror republish, brief unchanged), one DEGRADES and four
systemic notes (all fixed in the generator, corpus restamped, revalidated).

The generator has no account-specific checkout defaults. Pass all source
roots explicitly:

```text
python stamp-wave1.py --app-root <app-repo> --engine-root <engine-repo> --paid-root <paid-repo> [--out-root <output-parent>]
```

The launch chain likewise requires `CORPUS_ROOT` and `ENGINE_ROOT` in its
environment before it starts. It refuses a missing engine directory.

Selection rules (deterministic):
- s1-app-src: every .js under src/ and src/views/ (157), largest solo,
  smallest paired, exactly 150 lanes.
- s2-app-tests: every .test.mjs under tools/test/ (519), 3-4 per lane.
- s3-engine-src: the 150 largest of the enumerated engine src modules
  (458 enumerated: src/, src/lib/, and each first-level src/lib/* dir).
- s4-engine-tools: every tool (.js/.mjs/.cjs/.ps1) under tools/ (289 incl.
  release-packager and subdirs), grouped to 150.
- s5-products: all 58 non-test product source files (presentation-suite,
  scribe incl. engine .py, web-editor, shared) + 92 lanes over the 105
  product test files.
- s6-website: server/, website/tools/, testkit (non-test), deploy/, public
  page .js/.css (138 files, grouped) + 12 lanes over 61 site test files.

Dispatch: cloud-b ONLY (hand-written provider files; --provider auto would
round-robin half of each batch to the exhausted cloud-a). 43 launches/min
(3.47 min per 150), --accounts 1, batches strictly serial, a usage checkpoint
between batches, stop-and-report at >=90% used.
