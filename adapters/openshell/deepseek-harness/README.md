# Use ToolsEnabled Fleet with DeepSeek Harness

ToolsEnabled Fleet is compatible with [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH). DSH connects to Fleet as an MCP server through its built-in `@deepseek-ai/dsh-mcp-client` plugin. A DSH agent then sees Fleet's tools as `mcp__toolsenabled__<tool>`: the shared work record, memory, status and the other tools your Fleet tier allows.

ToolsEnabled is not affiliated with or endorsed by DeepSeek. "DeepSeek Harness" is a trademark of DeepSeek.

## What you need

- Fleet beta 3 (1.4.2) or later, installed and set up in an OpenShell sandbox with the [two-command install](https://github.com/ToolsEnabled/toolsenabled-engine/releases/tag/openshell-beta3-20261001). Setup registers Fleet with Codex and/or Claude Code; the helper below copies that registration.
- DeepSeek Harness in the **same sandbox**, for example `pip install deepseek-harness-sdk` (Python 3.10+) or `npx @deepseek-ai/dsh web` (Node.js). Your sandbox policy must let the installer reach PyPI or npm, and let the DSH binary reach your model provider. See the example policy below.
- A model provider for DSH: DeepSeek's API, or any OpenAI-compatible endpoint configured in DSH.

## 1. Create the DSH overlay

On your host, download the helper and copy it into the sandbox:

```bash
curl -fsSLO https://raw.githubusercontent.com/ToolsEnabled/toolsenabled-engine/openshell-beta-source-20260930/adapters/openshell/deepseek-harness/fleet-dsh-overlay.py
openshell sandbox upload SANDBOX_NAME fleet-dsh-overlay.py /sandbox/
```

Inside the sandbox:

```bash
python3 /sandbox/fleet-dsh-overlay.py
```

It reads Fleet's own `toolsenabled` entry from `~/.codex/config.toml` (Python 3.11+) or `~/.claude.json`, and writes `~/toolsenabled-fleet.cordis.yml` (mode 0600). It changes no other file and refuses to overwrite an existing overlay unless you pass `--force`. Re-run it after a Fleet upgrade. Options: `--from codex|claude`, `--output PATH`, `--cwd DIR`.

## 2. Start DSH with Fleet

```bash
dsh web --patch ~/toolsenabled-fleet.cordis.yml
```

With the Python SDK, pass the overlay in `patches`:

```python
from deepseek_harness import DeepSeekHarness, DeepSeekHarnessConfig

config = DeepSeekHarnessConfig(patches=("/sandbox/toolsenabled-fleet.cordis.yml",), cwd="/sandbox/work")
with DeepSeekHarness(config) as harness:
    print(harness.run("Using the ToolsEnabled Fleet tools, report Fleet's system status.").final_response)
```

To keep Fleet across runs, merge the overlay's single `insert` entry into your DSH patch layer (`$DSH_HOME/profiles/<profile>/cordis.patch.yml`). Don't overwrite an existing patch file.

## 3. Check it

Ask DSH: *"Using only the ToolsEnabled Fleet tools, report Fleet's system status and how many tasks are in the work record."* DSH discovers MCP tools asynchronously, so give it a few seconds after start.

## Limits

- **Tools follow your Fleet tier.** In the guided tier, agents get read-only task and memory tools; writes need the standard or unrestricted tier. This is the same for Codex and Claude Code.
- **No agent label yet.** Fleet records whether Codex or Claude acted. DSH actions are recorded without an agent label until a later release adds one.
- **Lead agent only.** DSH uses Fleet's tools; Fleet's worker tree still runs Codex and Claude Code workers.
- **Same sandbox.** The overlay starts Fleet's local MCP server over stdio, so DSH must run where Fleet is installed.

## Tested

On 2026-10-01: Fleet 1.4.2 (beta 3, installed from the public release) and the DeepSeek Harness Python SDK 0.1.5rc1, in a fresh OpenShell 0.1.2 sandbox. The model was DeepSeek V4.1 Flash (`deepseek-ai/deepseek-v4.1-flash`) through NVIDIA's OpenAI-compatible endpoint. DSH discovered Fleet's tools and called `capability.find`, `system.status`, `memory.search` and `task.list` in real sessions. The overlay above was generated by the helper and produced the same file from the Codex and Claude Code registrations.

## Example sandbox policy additions

Add rules like these to your OpenShell policy so the installer and DSH can reach the network. Adjust the binary paths to where you install DSH:

```yaml
network_policies:
  dsh_pypi:
    name: dsh_pypi
    endpoints:
      - { host: pypi.org, port: 443, protocol: rest, enforcement: enforce, access: read-only }
      - { host: files.pythonhosted.org, port: 443, protocol: rest, enforcement: enforce, access: read-only }
    binaries:
      - path: /usr/bin/python3*
      - path: /sandbox/dshvenv/bin/**
  dsh_model:
    name: dsh_model
    endpoints:
      - { host: api.deepseek.com, port: 443, protocol: rest, enforcement: enforce, access: read-write }
    binaries:
      - path: /sandbox/dshvenv/**
```
